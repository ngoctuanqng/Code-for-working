			Giải thích:

			- bin/kafka-storage.sh:
			  Là script dùng để quản lý và khởi tạo storage cho Kafka trong chế độ 
			  KRaft (Kafka Raft Metadata Mode).
			  
				Khởi tạo storage (hay format storage) cho Kafka trong chế độ KRaft 
				là thao tác chuẩn bị thư mục dữ liệu và ghi nhận mã định danh cụm 
				(Cluster ID) cùng file cấu hình metadata ban đầu trước khi khởi động 
				broker/controller.
				
				Ý nghĩa cụ thể của việc này bao gồm:
				
					Tạo mã định danh chung (Cluster ID): 
					
						Gắn kết các node (broker/controller) thành một cụm thống nhất 
						bằng một UUID duy nhất.
					
					Thiết lập phân vùng metadata: 
					
						Tạo file meta.properties trong thư mục log (log.dirs) để node 
						biết nó thuộc cụm nào và mang vai trò gì.
					
					Thay thế ZooKeeper: 
					
						Ở chế độ mới KRaft, Kafka không dùng ZooKeeper để lưu metadata 
						nữa mà tự quản lý qua nhật ký sự kiện (metadata log), do đó cần 
						khởi tạo không gian lưu trữ này thủ công trước khi chạy.

			- format:
			  Là tham số yêu cầu Kafka format (khởi tạo) thư mục lưu trữ dữ liệu trước khi 
			  cluster được khởi động lần đầu.

			- -t:
			  Viết tắt của "cluster id".
			  Chỉ định Cluster ID sẽ được ghi vào storage metadata.

			- $KAFKA_CLUSTER_ID:
			  Là biến môi trường chứa Cluster ID đã được tạo trước đó bằng lệnh:

			  KAFKA_CLUSTER_ID="$(bin/kafka-storage.sh random-uuid)"

			- -c:
			  Viết tắt của "config".
			  Chỉ định file cấu hình Kafka sẽ được sử dụng.

			- config/kraft/server.properties:
			  Là file cấu hình cho Kafka chạy ở chế độ KRaft.
			  File này chứa các thiết lập như:
			  - node.id
			  - log.dirs
			  - controller.quorum.voters
			  - listeners
			  - process.roles
			  - các thông số khác của broker và controller

			Quá trình thực thi:

			1. Kafka đọc file cấu hình:

			   config/kraft/server.properties

			2. Xác định thư mục lưu trữ dữ liệu từ thuộc tính:

			   log.dirs

			4. Tạo các file metadata cần thiết để Kafka có thể hoạt động ở chế độ KRaft.

			5. Storage được đánh dấu là đã được khởi tạo.

			Ví dụ:

			$ bin/kafka-storage.sh format -t $KAFKA_CLUSTER_ID -c config/kraft/server.properties

			Formatting /tmp/kraft-combined-logs with metadata.version 3.5-IV2.

			Lệnh này khởi tạo vùng lưu trữ metadata cho Kafka KRaft trước lần khởi động đầu

			- Nếu format lại trên storage đang chứa dữ liệu, metadata hiện có có thể bị ghi đè 
			hoặc gây lỗi khởi động.

		BẢN CHẤT KẾT NỐI

			Producer (Spring Boot) chạy trên Windows

			Kafka Broker + Consumer chạy trong WSL (Ubuntu)

		Windows ↔ WSL không phải 2 máy khác nhau, mà:

					|

					|

					|
			Kafka Consumer (WSL)

		ĐIỀU QUAN TRỌNG NHẤT: advertised.listeners

			Đây là chỗ 90% người mới bị lỗi.

			Cấu hình SAI (mặc định)

				Kafka trong WSL thường có:

					advertised.listeners=PLAINTEXT://localhost:9092

				→ Producer trên Windows sẽ KHÔNG kết nối được

			CẤU HÌNH ĐÚNG (KHI PRODUCER Ở WINDOWS)

				Trong server.properties (Kafka chạy WSL):

					listeners=PLAINTEXT://0.0.0.0:9092
					advertised.listeners=PLAINTEXT://localhost:9092


			Vì sao?

				0.0.0.0 → Kafka lắng nghe mọi interface

				localhost → Windows truy cập được WSL

		Bản chất listeners=PLAINTEXT://0.0.0.0:9092 là bắt buộc. Nó mở cửa cho phép 
		Kafka lắng nghe kết nối từ mọi card mạng (internal của WSL, card mạng ảo 
		kết nối với Windows, v.v.). Nếu để mặc định localhost ở dòng listeners, Kafka 
		sẽ chỉ chơi một mình trong nội bộ Ubuntu.
		
		Bản chất thật sự của advertised.listeners là gì?
		
			Khi Producer (Spring Boot ở Windows) kết nối lần đầu đến Kafka, nó 
			sẽ hỏi: "Chào Broker, tôi muốn gửi tin nhắn vào Topic A, tôi phải gửi 
			chính xác đến địa chỉ IP nào?".Kafka Broker sẽ lật file cấu hình ra, 
			lấy giá trị của advertised.listeners để trả lời cho Spring Boot.
				
				Nếu bạn để advertised.listeners=PLAINTEXT://localhost:9092: Kafka trả 
				về cho Spring Boot chữ localhost. Spring Boot (đang chạy ở Windows) sẽ 
				hiểu là "À, gửi vào localhost của chính Windows". Nhờ tính năng Port 
				Forwarding tự động của WSL2, Windows sẽ tự hiểu và chuyển tiếp gói 
				tin đó vào đúng WSL2. Cấu hình này chạy được.
				
				Vậy tại sao nhiều người vẫn lỗi? Đó là vì trên một số phiên bản WSL2 
				hoặc cấu hình mạng Windows cũ, tính năng tự động forward localhost bị 
				lỗi hoặc bị tắt. Lúc này, Kafka trả về localhost, Spring Boot ở Windows 
				kết nối vào localhost của Windows nhưng Windows không biết chuyển tiếp 
				đi đâu, dẫn đến lỗi Timeout hoặc Connection Refused.

			Trong đó:
			- user1, user2, user3 là Key.
			- Hello Kafka, Login Success, Logout là Value.

			Lưu ý:
			- Mặc định Key và Value được phân tách bằng ký tự TAB.
			- Nếu muốn sử dụng dấu ":" khi hiển thị:

			--property key.separator=":"

			Ví dụ:

			./kafka-console-consumer.sh \
			  --topic my-topic \
			  --from-beginning \
			  --bootstrap-server localhost:9092 \
			  --property print.key=true \
			  --property print.value=true \
			  --property key.separator=":"

			Kết quả:

			user1:Hello Kafka
			user2:Login Success
			user3:Logout

			Luồng hoạt động:

			Kafka Topic (my-topic)
					  |
					  | Key=user1 Value=Hello Kafka
					  | Key=user2 Value=Login Success
					  | Key=user3 Value=Logout
					  v
			Kafka Console Consumer
					  |
					  | print.key=true
					  | print.value=true
					  v
			Terminal hiển thị:
			user1    Hello Kafka
			user2    Login Success
			user3    Logout

			Kết luận:
			- kafka-console-consumer.sh: công cụ đọc dữ liệu từ Kafka.
			- --topic my-topic: topic cần đọc.
			- --from-beginning: đọc toàn bộ lịch sử message từ đầu topic.
			- --bootstrap-server localhost:9092: broker kết nối.
			- print.key=true: hiển thị Key.
			- print.value=true: hiển thị Value.
			- Tham số --from-beginning bị lặp nhưng không ảnh hưởng đến kết quả thực thi.

					@PostMapping

						String productId;

				package com.appsdeveloperblog.ws.products.service;

				import com.appsdeveloperblog.ws.core.ProductCreatedEvent;
				import com.appsdeveloperblog.ws.products.rest.CreateProductRestModel;
				import org.slf4j.Logger;
				import org.slf4j.LoggerFactory;
				import org.springframework.http.HttpStatus;
				import org.springframework.http.ResponseEntity;
				import org.springframework.kafka.core.KafkaTemplate;
				import org.springframework.kafka.support.SendResult;
				import org.springframework.stereotype.Service;

				import java.util.UUID;
				import java.util.concurrent.CompletableFuture;

				@Service
				public class ProductServiceImpl implements ProductService {

					KafkaTemplate<String, ProductCreatedEvent> kafkaTemplate;

					private final Logger LOGGER = LoggerFactory.getLogger(this.getClass());

					public ProductServiceImpl(KafkaTemplate<String, ProductCreatedEvent> kafkaTemplate) {
						this.kafkaTemplate = kafkaTemplate;
					}

					@Override
					public String createProduct(CreateProductRestModel productRestModel) throws Exception {
						String productId = UUID.randomUUID().toString();

						ProductCreatedEvent productCreatedEvent = new ProductCreatedEvent(productId,
								productRestModel.getTitle(), productRestModel.getPrice(),
								productRestModel.getQuantity());

						LOGGER.info("Before publising a ProductCreatedEvent");

						SendResult<String, ProductCreatedEvent> result =
								kafkaTemplate.send("product-created-events-topic", productId, productCreatedEvent).get();

						LOGGER.info("Partition: " + result.getRecordMetadata().partition());
						LOGGER.info("Topic: " + result.getRecordMetadata().topic());
						LOGGER.info("Offset: " + result.getRecordMetadata().offset());

						LOGGER.info("Returning product id");

						return productId;
					}
				}

					import org.springframework.kafka.core.ConsumerFactory;

					import org.springframework.kafka.support.serializer.ErrorHandlingDeserializer;

						@Autowired

						@Bean

							Map<String, Object> config = new HashMap<>();
							config.put(ConsumerConfig.BOOTSTRAP_SERVERS_CONFIG,
									environment.getProperty("spring.kafka.consumer.bootstrap-servers"));
							config.put(ConsumerConfig.KEY_DESERIALIZER_CLASS_CONFIG,
									StringDeserializer.class);
					//        config.put(ConsumerConfig.VALUE_DESERIALIZER_CLASS_CONFIG,
					//                JsonDeserializer.class);
					//        config.put(JsonDeserializer.TRUSTED_PACKAGES,
					//                environment.getProperty("spring.kafka.consumer.properties.spring.json.trusted.packages"));

							config.put(ConsumerConfig.GROUP_ID_CONFIG,
									environment.getProperty("spring.kafka.consumer.group-id"));

							// 🔥 CHUẨN MỚI – KHÔNG DEPRECATED
							config.put(
									ConsumerConfig.VALUE_DESERIALIZER_CLASS_CONFIG,
									ErrorHandlingDeserializer.class
							);

							config.put(
									ErrorHandlingDeserializer.VALUE_DESERIALIZER_CLASS,
									JsonDeserializer.class
							);

							// Khai báo type rõ ràng (RẤT QUAN TRỌNG)
							config.put(
									JsonDeserializer.VALUE_DEFAULT_TYPE,
									"com.appsdeveloperblog.ws.core.ProductCreatedEvent"
							);

							config.put(
									JsonDeserializer.TRUSTED_PACKAGES,
									"com.appsdeveloperblog.ws.EmailNotificationMicroservice"
							);



							return new DefaultKafkaConsumerFactory<>(config);
						}

						@Bean
						ConcurrentKafkaListenerContainerFactory<String, Object> kafkaListenerContainerFactory(
								ConsumerFactory<String, Object> consumerFactory) {

							String productId = UUID.randomUUID().toString();
